# Управление задачами

В TaskTracker задача — центральный объект: к ней привязаны обсуждения, вложения, история изменений и связи с другими задачами.

## Создание и редактирование

### Основные поля

| Поле | Назначение |
|------|------------|
| Заголовок | Краткое название; отображается в списках и на доске |
| Описание | Детали, критерии приёмки; поддерживается Markdown |
| Статус | Колонка workflow (зависит от настроек проекта) |
| Приоритет | Низкий / Средний / Высокий / Срочный |
| Исполнитель | Ответственный за выполнение |
| Срок | Дата и опционально время дедлайна |
| Метки | Теги для фильтрации (например, `backend`, `bug`) |

### Шаблоны описания

В настройках проекта можно задать **шаблон по умолчанию** для новых задач — например, блоки «Проблема», «Предлагаемое решение», «Тестирование».

!!! tip "Упоминания"
    В описании и комментариях введите `@имя` — пользователь получит уведомление. Упоминания работают и для групп, если они настроены администратором.

## Комментарии и история

- **Комментарии** хранятся в хронологическом порядке; можно редактировать и удалять свои в течение ограниченного времени (если политика организации это разрешает).
- Вкладка **«История»** показывает смену статуса, исполнителя, сроков и меток с указанием автора и времени.

## Связи между задачами

Доступные типы связей (зависят от конфигурации проекта):

- **Блокирует / заблокирована** — одна задача не может быть закрыта, пока открыта другая.
- **Связана с** — общая тема без жёсткой зависимости.
- **Дубликат** — объединение повторяющихся тикетов.

Пример: задача `ALF-10` «API каталога» блокирует `ALF-11` «Вёрстка списка товаров», пока API не готов.

## Вложения и чек-листы

- Загрузите файлы перетаскиванием или через кнопку **«Вложение»**; допустимые типы и размер задаёт администратор.
- **Чек-листы** внутри задачи позволяют разбить работу на подпункты без создания отдельных задач.

## Фильтры и поиск

На странице списка задач используйте:

- полнотекстовый поиск по заголовку и описанию;
- фильтры по исполнителю, статусу, меткам и диапазону дат;
- сохранённые представления (**«Сохранить как»**) для повторяющихся запросов.

!!! note "Синтаксис поиска"
    В строке поиска можно комбинировать условия: `status:done label:bug` — завершённые задачи с меткой `bug`. Точный синтаксис см. в подсказке под полем поиска в интерфейсе.

## Закрытие и архивация

- Задача **закрывается** при переводе в терминальный статус (часто «Готово» или «Отменено»).
- **Архивация** на уровне проекта скрывает старые задачи из досок по умолчанию, но сохраняет их для отчётов и API.

!!! warning "Удаление"
    Удаление задачи необратимо для обычных участников и может быть запрещено политикой. Предпочтительно закрывать с комментарием причины.

## Отчёты (кратко)

В разделе **«Отчёты»** проекта доступны:

- распределение задач по статусам и исполнителям;
- burn-down по спринту (если включены спринты);
- экспорт в CSV для внешней аналитики.

Подробности экспорта и лимиты запросов к API описаны в [обзоре API](../api/overview.md).
